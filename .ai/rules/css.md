# Css

## Theme palette is derived from the brand logo, and a test enforces the pre-hydration pair
The palette comes from public/logo.png, not from a stock SaaS template: primary is the logo's navy #304364 (9.9:1 on white), and the logo's lime #92C14F is too light to carry text or act as an indicator (2.1:1 on white) so availability/confirmation states use the darkened #527A22 via the success-* tokens. Never recolour the logo itself — AppLogoIcon renders it full-colour on a neutral surface, never on a coloured tile.

Values are stored as oklch. When changing --background in either :root or .dark you must also change the matching inline style in resources/views/app.blade.php — that inline block paints the page before hydration. tests/Feature/AppearanceTest.php reads both --background values straight out of app.css and asserts the blade agrees, so the two cannot silently drift; it does not pin any particular colour.

The design system this came from is checked in at design-system/tx-bookings/MASTER.md (generated by the ui-ux-pro-max skill, then hand-corrected to the brand palette).

## Palette is Calendly-style vibrant blue on bluish white (supersedes the logo navy)
As of 2026-08-25 the theme is no longer derived from public/logo.png. Primary is the Calendly blue #006BFF = oklch(0.573 0.235 260.1), 4.62:1 against white so white-on-primary passes AA for normal text. Light --background is a bluish white oklch(0.979 0.007 255) with --card left pure white, so cards read as raised off a tinted page. Dark primary inverts to oklch(0.688 0.163 255) with a dark --primary-foreground.

There is now a fixed `--brand` / `--brand-foreground` pair defined only in :root and deliberately NOT overridden in .dark. It exists for the one surface that must stay brand blue in both themes: the AuthSplitLayout marketing panel. Use bg-brand/text-brand-foreground there, never bg-primary, which inverts to a light blue under .dark. Do not add more brand-* surfaces without a reason.

Success stays green (availability/confirmation) and is unchanged. The earlier rule that the palette comes from the logo's navy #304364 and lime #92C14F is obsolete; design-system/tx-bookings/MASTER.md still documents that old palette and is stale.

Unchanged: values are oklch, and changing --background in either block requires the matching edit in resources/views/app.blade.php, which tests/Feature/AppearanceTest.php enforces.
